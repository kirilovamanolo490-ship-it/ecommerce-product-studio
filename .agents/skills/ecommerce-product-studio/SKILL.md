# 本地电商商品视觉生产

目的：让每张图有独立的购买决策任务，让整套图有顺序，让产品外观和事实有依据，让改文案无需重生成整张照片。当前技能是 Agent 执行流程；附带脚本只建立任务档案和验证结构，不是独立生图软件。

## 入口与素材

1. 优先定位用户指定的商品目录。最低输入为一张可读取的真实产品图与名称/品类；手册、参数、文案、品牌参考都可补充。没有真实商品时完成流程或规划，不拿虚构商品冒充该商品成品。
2. 若需新建任务，运行 `scripts/project.py init <项目目录> --name <商品名> --image <照片路径>`。输入照片会复制到任务中并记录哈希，原文件不改动。其他手册复制到 `input/` 后加入 `product.json` 的 `sources`。
3. 逐图看原始产品；读取 PDF/DOCX 手册时使用相应文档工具，表格/图注不能只靠摘要。把目标平台、站点、语言记入档案；未知时仍可制作通用设计稿，但平台发布状态保持未核验。
4. 将可见外观、用户明确提供的参数、存在冲突的资料分开。`claims` 每条记录来源文件及页码/原句位置。画面可见的颜色不等于可证实材质；手册中的宣传句不自动证明检测或认证。

## 先规划购买逻辑

先明确要制作的是中文店铺营销封面、目录首图、图库辅图还是详情模块。用户要求营销表达，或反馈“太素、认不出品类、缺元素”时，读取 [main-image-design-grammar.md](references/main-image-design-grammar.md)，先建立逐页角色、元素作用、层级与阅读顺序，再写生图提示。营销封面须同时考虑商品身份、品类、用途/购买理由和支持信息；纯商品白底图按用户要求或已核验槽位需要选择。不要用减少产品出现次数、删除装饰或九个独立参数代替设计判断。

阅读 [storytelling.md](references/storytelling.md)。输出商品定位、前三个有依据的购买理由、主图分镜、详情分镜；主图最多 9 张，详情不固定数量。每页写清买家问题、一个结论、视觉证据、文案、claim 引用、素材需求和生成方式。图片上传上限取用户要求与已核验平台限制中更严格者。

`product.json` 是事实来源，`storyboard.json` 是页面计划；不要将二者合成一篇长提示词。声明尚未确定的需求，删除无证据或重复模块。首图可以仅为干净产品照，营销信息承接到后续页面；不能预设三个平台都允许相同九图和长详情。

## 统一商业视觉并生成

阅读 [production-and-editing.md](references/production-and-editing.md)。锁定产品轮廓、比例、结构、配件、颜色、标识、可用视角；统一摄影光线、色彩、字体、留白和画面节奏。无背面或内部证据时不创造结构细节。

通常先做一张主视觉与一张信息型页面，在内部检查身份、质感、移动端可读性后扩展；用户已授权直接完成时不把每个阶段变成确认门。每次生成附真实产品参考，不能只传文字。优先使用当前环境已有的图像生成/编辑工具；执行时读取其 imagegen 技能并遵守当时工具协议，不指定不存在的模型或参数，不静默切换服务。

背景、场景或需要修复的视觉区域用生图；精确标题、参数、尺寸线、品牌文件、脚注用可编辑对象排版。保留无文字视觉资产。包装自带文字属于产品身份，单独核对。原图优先路线不能承诺 AI 永不改动像素，必要时保留原始产品图层。

## 母版、改稿与交付

- `assets/` 保存产品图层、背景、场景和生成记录；`masters/` 保存实际可编辑项目；`exports/` 保存用户查看/平台上传图片；`qa/` 保存逐图检查和总览。
- 母版至少有独立文本、商品图片、背景与标注对象。JSON 规划文件不等于已经接通画布。HTML 可在源代码改排版，PNG/JPEG 是合并位图；不把这些差异隐藏成“全可编辑”。
- 改字/语言/参数优先改文字层；改版式改布局；只在需要更换视觉区域时重生成相关资产。保存新版，更新依赖页，保留未受影响的合格图片。
- 运行 `scripts/project.py validate <项目目录>` 检查计划引用与数量。它不证明画质、事实真伪或平台合规；这些须查看源文件与最终图。
- 交付前检查原图与成图、整套总览、手机宽度阅读、输出尺寸、文字溢出、单位、语言、商品结构。实际保存关闭并重新打开母版，完成一次标题改字、产品换图、重新导出，才能报告编辑闭环通过。
- 汇报已生成、已质检、可编辑实测、平台待适配分别是什么状态。没有真实生成和复测，不把模板或第三方 README 能力写成已完成。
