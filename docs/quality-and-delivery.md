# 质量验收与交付

至少区分四个状态：结构检查、视觉检查、编辑闭环、平台适配。每项都需要对应证据，不以文件存在或脚本退出成功代替。

## 结构检查

运行 `project.py validate <任务目录>`，保存输出。确认四份 JSON 可读、引用完整、来源文件与哈希一致、主图不超过 9 页。页面 ID 应稳定，便于对照版本。

这一步发现的是档案问题；它不会验证参数是否真实、图片是否清晰或页面是否可读。

## 真实商品与商业视觉检查

在整套总览、实际图片尺寸和约 390 像素宽手机视图中检查所有要求的主图与详情模块：

| 检查项 | 实际观察什么 |
|---|---|
| 身份一致 | 与原图对照轮廓、颜色、接口、数量、配件、标识和 SKU |
| 事实一致 | 参数/单位/语言与来源一致，条件没有被省略或扩大 |
| 页面任务 | 看完这一页是否形成了新的购买判断 |
| 阅读顺序 | 第一眼能否识别商品、核心结论和必要条件 |
| 移动端可读 | 标题、参数、说明有足够字号和对比，文字不过密 |
| 图像可信 | 场景与光线自然，产品不形变，示意不冒充实拍证据 |
| 版面完整 | 无意外裁切、溢出、遮挡，标注指向正确 |
| 整套节奏 | 场景、整体、细节、操作和规格相互补充，不重复堆卖点 |

留存问题页号、问题说明、修复动作和复查结果。若只有主图被检查，不能报告整套详情也通过。视觉尚未获审阅确认时写“待复核”，不要用技术测试替代设计接受。

## 可编辑闭环

在目标编辑器中真实执行，测试副本保存到 `qa/`：

1. 打开正式母版，核对页数、顺序、尺寸和图片加载。
2. 双击一段真实标题并修改文字，确认它是文本对象。
3. 替换一张图片，确认文字与背景仍可分别编辑。
4. 切到其他页面再返回，确认更改没有丢失。
5. 导出整个项目到一个新 JSON 文件，保留页面顺序和对象信息。
6. 关闭编辑页面，再重新进入编辑器并打开保存文件。
7. 核对修改、页数、顺序、字体和资源，再从界面导出一张 PNG。

只在浏览器里看到页面、截图、JSON 能解析或自动渲染成功，都不足以完成这项验收。记录操作环境、日期、输入母版、保存副本、导出文件和异常。

AI 场景照片仍是一张位图；不能宣称其中每个物件可分别编辑。PNG/JPEG 是交付预览，不是可编辑母版。PSD/SVG 的文件后缀或导出按钮也不能证明文字保持原生对象。

## 建议交付结构

```text
masters/    正式原生工程与必须关联的资源
assets/     最终使用的产品、背景、场景资产与生成记录
exports/    主图、独立详情模块及必要的长图/切片
qa/         总览、逐页复核、编辑测试副本与结果
product.json / storyboard.json / style.json / status.json
```

提供清单，逐项写文件名、用途、版本、页面数量、原生尺寸、导出尺寸、字体要求、示意说明和未完成项。长详情图只是查看或切分母图时，应明确标注，不承诺任意平台均能直接上传。

## 平台适配与发布

实际目标确定后核查平台、站点、类目、首图规则、图库数量、文字、尺寸、文件大小、格式和详情组织方式。核验日期与规则来源留在任务里。内部主图最多 9 张的约束不取代平台限制。

状态分别使用“已生成”“已检查”“可编辑实测通过”“平台待适配”“已提交”“已上线”等准确描述。GitHub 公开核心流程不代表商品已上传到任何电商平台。
