# 电商商品视觉工作室 · Ecommerce Product Studio

把真实商品照片、说明书和文案整理成有依据的商品档案，再按购买决策制作 **最多 9 张主图、数量可伸缩的详情模块，以及可继续改字、换图的画布母版**。

这个仓库公开的是一套可执行的 Agent 工作流程、任务档案工具和本地编辑器复现方法。它适合有真实商品素材、需要反复改稿的商品运营与设计协作。图片生成由执行环境中的图像工具完成；仓库本身不包含模型、API 额度或无人值守生图服务。

## 能做什么，做到哪一步

| 环节 | 当前实现 | 需要人或 Agent 继续完成的部分 |
|---|---|---|
| 建立任务 | Python CLI 复制原图、记 SHA-256、建立四份 JSON 和五个素材目录 | 实际打开图片和说明书，确认型号与资料版本 |
| 组织事实 | `sources`、`claims`、`identity_lock` 记录来源和外观约束 | 判断证据是否支持文案，处理冲突 |
| 规划图组 | 主图不超过 9 张，详情按信息量安排；每页绑定问题、结论与证据 | 根据商品选择页面顺序和视觉表达 |
| 生成素材 | 技能规定参考图、产品保真、视觉资产与文案分层的方法 | 使用当前环境实际可用的图像生成/编辑工具 |
| 编辑母版 | 固定 yft-design 上游源码与本地覆盖文件，可重建对象画布 | 将页面计划落实为文字、图片、形状对象 |
| 结构检查 | CLI 检查文件、引用、哈希、主图数量和关键字段 | 视觉、语义、字体、真实编辑闭环检查 |
| 平台适配 | 档案预留平台、站点和语言字段 | 到实际站点核查规格并另行执行上传发布 |

`storyboard.json` 是策划数据，**不能直接当作编辑器工程导入**。本项目还没有面向任意商品的一键编译器、通用队列、模型 API 调度或平台发布器。编辑器在线模板、PDF/PSD 转换等依赖额外后台，详见编辑器文档。

## 核心流程

```mermaid
flowchart LR
    A[真实照片与说明书] --> B[商品档案与事实来源]
    B --> C[主图与详情分镜]
    C --> D[风格与产品身份约束]
    D --> E[参考图生成或保留实拍]
    E --> F[文字 图片 标注分层排版]
    F --> G[逐图与整套视觉检查]
    G --> H[改字 换图 保存 重开 导出]
    H --> I[母版 素材 导出图 QA记录]
```

每一张图回答一个买家问题。首图让人认出商品与主要用途，后续页面补充理由、证据、使用条件与购买顾虑。主图的“最多 9 张”是本项目制作约束，不代表任意平台允许上传 9 张；详情也不预设必须做成某个长度。

## 最小使用方式

需要 Python 3.9 或以上。以下命令在仓库根目录执行，图片路径替换成你有权使用的真实文件：

```sh
python3 .agents/skills/ecommerce-product-studio/scripts/project.py init products/sku-001 \
  --name '商品名称' \
  --image '/path/to/your-product.jpg'
```

这一步只建立档案。补齐 `product.json`、`storyboard.json` 和 `style.json` 后，再检查结构：

```sh
python3 .agents/skills/ecommerce-product-studio/scripts/project.py validate products/sku-001
```

新任务的分镜为空，验证返回退出码 `1` 是正常结果。仓库附有可通过结构校验的演示：

```sh
python3 .agents/skills/ecommerce-product-studio/scripts/project.py validate examples/planning-only
```

演示图是程序绘制的占位示意，不是商品照片，不可作为实际商品宣传。完整操作见[快速开始](docs/quickstart.md)。

在支持项目技能的 Agent 环境中，可以使用下面的任务描述：

> 使用本仓库的 ecommerce-product-studio 技能，读取 products/sku-001 的真实素材。核对商品身份和说明书版本，建立可追溯事实，规划最多 9 张主图与按信息量安排的详情模块。先完成核心页面方向，再扩展整套。精确文案使用独立文本层，保留可编辑工程与素材。实际执行改字、换图、保存、关闭、重新打开和导出检查，分别报告生成、视觉验收、编辑验收与平台适配状态。

如果你的环境不能自动发现技能，可直接让 Agent 阅读仓库中的 `SKILL.md`。使用流程不依赖安装 `github/` 中的研究技能。

```text
.agents/skills/ecommerce-product-studio/
  SKILL.md                  Agent 执行入口
  scripts/project.py        初始化与结构校验
  references/               事实、分镜、设计语法、分层生产约定
apps/editor-yft/             编辑器说明、来源、许可证和本地覆盖文件
scripts/                    固定版本编辑器重建工具
examples/                   无品牌、无客户素材的结构和画布演示
docs/                       快速开始、完整流程、协议、验收与公开说明
products/README.md          新任务目录入口；真实任务默认忽略
```

完整本地工作区另外可能有 `Product/`、`github/`、`research/`、`workspace/`。这些目录分别承载品牌研究样本、第三方快照、过程记录和运行环境；不随本次核心仓库整体发布。`Product` 与 `products` 在部分文件系统上只差大小写，不应在跨平台协作时用来建立两套并行商品目录；公开任务统一使用小写 `products/`。

## 设计与修改原则

- 产品外观以真实参考为准：轮廓、比例、颜色、接口、配件、标识与 SKU 不随场景任意改变。
- 参数和功能写明来源及定位。待核实或相互冲突的宣称不能进入已确认页面。
- 无背面、内部或拆解证据时调整页面内容，不能靠想象补出结构。
- 生图用于视觉素材；准确标题、参数、规格线和脚注使用可编辑对象。
- 改字先改文本层，改背景只改相关资产，换 SKU 先重新核对事实；保留版本与未受影响页面。
- 同时检查缩略图、手机宽度、单页原尺寸和整套顺序；文字边界检查不能代替商业视觉判断。

## 验证与项目状态

历史本地记录显示，编辑器已进行中文改字、图片替换、整套 JSON 保存重开及当前页 PNG 导出测试。该记录只证明特定版本和测试环境下的编辑操作，不代表任意商品稿、浏览器或正式部署已验收。

本地 C200 案例用于发展流程，其中早期版本的商业视觉曾被否定；因此公开说明不会把“文件生成了”“技术检查通过”写成“商业成图获认可”。商品案例原图、手册、母版和生成大文件留在本地。本次仓库的实际检查记录见 [验证记录](docs/verification.md)。
