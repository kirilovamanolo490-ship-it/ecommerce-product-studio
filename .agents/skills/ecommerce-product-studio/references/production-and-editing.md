# 视觉生产与后续编辑

## 最小可行的生产链

本地档案 → 商品事实与身份锁 → 图组分镜 → 风格规范 → 少量样张 → 独立视觉资产 → 文案图层排版 → 总览与逐图质检 → 母版及图片交付。

“本地”首先指原图、资料、项目与输出保存在本机。当前生图可由环境内置工具执行；不等于断网可用的本地模型，也不是后台自动监听文件夹的无人值守程序。以后接 API 时再实现任务队列、费用上限、失败重试与 provider 配置。

## 产品保真优先级

1. 规格、包装和精密结构图：优先保留真实照片作为图片对象；文字和标注另排。
2. 场景/氛围图：带产品参考生成，检查轮廓、接口、手柄、纹理、颜色、配件数量；发现漂移就修受影响资产。
3. 微距、背面、内部结构、拆解图：只在有对应原始素材或可靠结构证据时做。单张正面图不够时换视觉任务，或明确需要补图。

避免每一张都换一种产品姿态来表现“丰富”。远景、整体、细节、使用、标注的节奏比随机换背景更有商业价值。虚构前后效果、测试图表、用户评价不是视觉设计手法。

## 风格规范

保留一份 `style.json`：品牌定位、2–3个基础色和强调色、字体及授权来源、标题/正文/注释层级、网格与安全区、棚拍或场景光线、产品比例、允许的道具、禁止漂移项。色值和字体是本套图选择，不是所有商品的统一模板。

先选角色：质感型商品让材质与光影说话；功能型商品优先展示使用过程；参数型商品用准确标注和层级解释。促销贴纸、金属渐变、密集大字不能替代定位。让主图缩略图一眼认出产品，让详情页每一屏快速读懂一个结论。

## 可编辑的四种含义

| 形式 | 真正能改什么 | 使用边界 |
|---|---|---|
| 提示词+PNG | 改提示词重新生成，位图局部修图 | 已烧进照片的文字不是文本对象 |
| HTML/CSS+本地素材 | 改字、改排版、换图再渲染 | 源码可编辑，未必能拖拽 |
| 画布 JSON+素材包 | 文本/图像/形状对象可拖动和修改 | 必须验证目标编辑器保存/重开与字体/资源绑定 |
| PSD | 取决于实际导出的图层和文字类型 | 文件后缀或“导出PSD”按钮不证明文本可编辑 |

推荐母版以对象图层为准：`background`、`product`、`headline`、`body`、`dimension-lines`、`footnote`；稳定对象 ID 与页面 ID 便于局部修订。AI生成的场景仍可能是单张位图，不能声称其中每个物件都可编辑。

自有 `storyboard.json` 为规划协议，不能直接冒称 yft-design 导入格式。C200 实例已将它编译成 Fabric 对象/编辑器原生 JSON，图片以 data URI 嵌入；其他商品仍需按分镜调整模板。画布改动要回写母版，不能下一次导出又被旧文案覆盖。

## 局部修改原则

改标题只变文字层；换语言重排对应页面；换 SKU 先核查颜色/尺寸/包装并更新相关事实和资产；改背景保留产品层；改真实结构先更新源图。记录页号、对象 ID、旧值、新值、来源与输出版本。重新检查发生变化的页面和图组一致性。

## 导出与实际验收

源分辨率不足时不能用放大后的像素数冒充更多细节。目标平台未知时只导出标明用途的设计预览；平台确定后再建立经核验的 export profile（站点、类目、官方链接、核查日期、图库数量/比例/大小、详情机制）。中文平台长图不能自动等同于 TikTok Shop/TEMU 的上传结构。

详情页先保存独立模块，长图只是预览或特定平台的派生输出。切片避开标题、产品主体和参数表；模块数由购买逻辑决定，平台单次上传受限时由导出器分组，不把内部模块数量写死。

至少用一次真实商品完成：原图对照 → 主图/详情抽样视觉检查 → 全套文字和规格检查 → 手机阅读 → 母版保存关闭重开 → 改字换图 → 再导出。没有完成这条链路前，用“流程已沉淀/代码已研究”，不要用“自动生产系统已上线”。


## 已验证的 C200 本地画布实例

`Product/05-tapo-c200/production/` 是21页真实生成实例。yft 图层 `name` 应用原生类型名（如 `textbox`、`image`），语义角色放在稳定 `id`，否则右侧编辑属性面板可能不出现。完整项目通过“打开项目 JSON”替换工作区，通过“保存整个项目 JSON”保存所有页；不要把追加模板当作打开项目，也不要把当前页导出当作保存整套工程。浏览器复测覆盖切页同步、改字、换图、保存重开与PNG导出。
